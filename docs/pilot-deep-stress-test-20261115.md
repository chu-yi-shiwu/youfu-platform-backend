## 4. 资源与稳定性

```text
采样 26 次（每 5s）：
  Node RSS：113MB（低）～197MB（峰值）→ 结束 129MB
  CPU：峰值 4.6%
  DB 连接：峰值 22（池 20 + 系统），结束 11（active 1 / idle 10）
  服务健康：全程 ready，无 5xx、无连接超时
```

判断：
- 200 并发读时 p95 601ms，主要由 20 连接池排队造成，无 5xx；当前 pilot 业务量下可接受。
- soak 后 RSS 回落，未观察到持续增长；无连接泄漏。
- 竞争场景均保持“恰 1 成功/精确库存”，说明行锁与条件更新在 50 并发下仍成立。

## 5. 本轮发现

## 7. 风险与建议

- 连接池 max=20：200 并发读 p95 约 0.6s；若未来并发持续升高，建议按 `CPU×4` 评估调大池并压测 400/800 并发。
- 1 万单大列表 p95 109ms 表现良好；更深的 offset（>5 万）未测。
- 压力测试在 pilot 单实例上执行，未覆盖多实例/负载均衡；主站与 pilot 共享 ECS，压测期间主站未受影响（load average < 1.2）。
- 登录限频按 IP 10 次/分钟，压测脚本使用 JWT 直签绕过登录；真实客户端批量登录会受 429 限制，属预期。
