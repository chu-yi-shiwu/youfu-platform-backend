## 4. 根因修复 D21（本轮新增）

### 4.1 现象

主站轻量压力复测（同一套代码、同一台 ECS）：

```text
主站：20 并发建单 p95 3.2s，流转 p95 2.0s，30s soak p95 1.45s
pilot：20 并发建单 p95 0.24s，流转 p95 0.11s，120s soak p95 0.05s
```

差异只在环境：主站 `.env` 配了 `EMBEDDING_API_KEY`，pilot 未配。

### 4.2 根因（不是“机器慢”）

1. `repo/ticket.ts` 建单后只判断 `embeddingConfigured()`（全局 key），**未检查租户 `ai_features_enabled`**。主站所有租户（包括 UAT 压测租户）都会触发嵌入。
2. 嵌入调用虽是 fire-and-forget，但**没有并发上限**。20/50 并发建单产生 100+ 个外部 embedding 请求同时挂起，拖慢事件循环与出站连接，连带把同期流转请求拖到 2s。

### 4.3 修复（根因层）

- 租户门：`getAiFeaturesEnabled(tenantId, client)` 在事务内复用同一连接读取开关；未开启（默认 false）⇒ 不产生嵌入任务。
- 有界队列：新增 `services/embeddingQueue.ts`，全局 **2 并发 / 200 上限**；超限丢弃并告警，禁止无限堆积。
- 嵌入仍在后台 best-effort 执行，不阻塞建单；失败只告警。

### 4.4 复测结果

```text
主站：建单 p95 3.2s → 355ms；流转 p95 2.0s → 127ms；soak p95 1.45s → 22ms
pilot：建单 p95 0.24s → 0.56s（波动范围内）；soak p95 0.05s → 0.06s
0 个 5xx；主站/ pilot 服务与数据库无连接泄漏
```

负控制：`src/test/embeddingQueueScope.test.ts` —— 并发不超过 2、队列满丢弃、租户门在入队之前。
