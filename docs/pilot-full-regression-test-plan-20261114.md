# 全模块全量测试与集成测试方案（2026-11-14）

> 原则：本轮**从零建立基线**，不引用历史测试结论，不把既有脚本的“通过”当作证据；历史脚本只作为工具复用，结论以本轮实测数据为准。
> 目标：所有模块业务流程完整闭环、功能点无异常、跨模块流转正常、小程序全流程可用。

## 0. 测试目标

1. 每个模块的**正向闭环**可完成；
2. 每个模块的**负向/边界/权限**符合契约；
3. 跨模块**状态、数据、金额、库存、积分、通知**一致；
4. 小程序**角色首页 → 模块 → 操作 → 返回/切 Tab** 无死路；
5. 所有写操作有**审计/留痕/可回滚**路径；
6. 测试数据**可清理、可复现、可审计**。

## 5. 跨模块集成链（必须全过）

### X1 报修全链

```text

→ 复核通过 → 评价 → 自动结算草稿 → 确认 → 导出
```


## 6. 数据不变量

```text
I1  工单 status 与事件序列一致，无未知态
I2  signup_count = 记录数；signup_count <= slots
I3  库存 qty = 入库 - 出库 - 消耗 + 退库
I4  结算明细金额 = 价 × 量；表头 total = 明细和
I5  confirmed 结算锁定；voided 不可导出
I6  资产 repairing 在工单完成后回写 in_use
I7  巡检 overdue = 未完成且 scheduled_at < now()
I8  巡更 checkins 不含未指派点位；via 可审计
I9  志愿者黑名单/签到码租户内唯一
I10 通知 recipient 仅本人；孤儿不展示
I11 基础数据停用不影响历史解析
I12 跨租户零泄漏
I13 幂等键重放不产生重复业务
I14 CSV 导出可被导入 roundtrip
I15 所有写操作有事件/审计留痕
```
