# 志愿者活动模块全面测试方案（2026-11-14）

## 0. 目标

按前几轮的方式，对志愿者模块做一次**真实 API + 真实库 + PC + 小程序 + 真机**的完整功能测试：

1. 所有已实现功能闭环是否正常；
2. 新增增强（编辑/删除/详情/导出/签到码/积分规则/黑名单/取消截止/变更通知）是否完整；
3. 权限、租户隔离、并发、边界、异常是否可靠；
4. 主动发现新问题；若没有，给出覆盖率和残余风险说明。

## 1. 测试范围

### 1.1 功能点

```text
活动：创建、编辑、删除、列表、详情、关闭、重开、过期状态
报名：报名、重复拦截、满员、关闭/结束/截止拦截、黑名单拦截
取消：本人取消、管理员取消、取消截止、释放名额
签到：本人签到、扫码签到、时间窗、补签、重复签到
签退：时长、积分、积分规则、状态机
核销：仅已签退可核销
统计：活动人数、服务人次/时长/积分、人员档案
导出：报名名单 CSV（中文表头/值/日期/补签）
通知：活动变更站内信、通知列表可见、无孤儿
配置：积分规则、黑名单
```

### 1.2 端

```text
后端 API + 数据库
PC 志愿者活动页
小程序志愿者列表 / 活动详情页 / 扫码签到
iPad / HarmonyOS 真机（如可用）
```

### 1.3 不纳入

- 微信订阅消息（志愿者变更通知本轮只发站内信）；
- 活动报名收费/保险/排班等未实现业务；
- 网络层渗透测试。

## 2. 环境与数据

| 用途 | 租户 |
| --- | --- |
| API 功能/并发/边界 | `uat-vol-<run>` 隔离租户 |
| PC 页面写操作 | `uat-vol-ui-<run>`（UAT admin 登录），或真实租户仅建 1 个无报名活动后删除 |
| 小程序/真机 | `uat-vol-mp-<run>` 或真实 pilot 只读活动 |
| 真实租户 | 不写业务数据；仅在必要时建 1 个无报名活动并删除 |

数据规则：

```text
活动标题统一前缀 VOL-TEST-
志愿者姓名统一前缀 测试-
黑名单/积分规则只改 UAT 租户
测试结束按 tenant_id 清理；校验租户/活动/记录/黑名单为 0
证据中手机号/openid 脱敏
```

## 3. 测试分层

```text
L0 静态：tsc / build / 迁移检查
L1 单测：volunteer 相关后端/前端用例
L2 API E2E：隔离租户全功能 + 负向 + 边界 + 并发
L3 PC E2E：Playwright 真实页面
L4 小程序：API + 预览码 + 真机
L5 非功能：权限/隔离/并发/安全/可靠性/轻量性能
L6 门禁：全量回归、清理、报告
```

## 5. 数据不变量

```text
I1 signup_count = volunteer_record 行数
I2 signup_count <= slots（取消/编辑后同样成立）
I3 每条记录状态 ∈ registered/checked_in/checked_out/approved
I4 duration_min/points 与签到/签退时间、积分规则一致
I5 黑名单 (tenant,user_name) 唯一
I6 checkin_code (tenant,code) 唯一
I7 活动删除后无孤儿记录/通知
I8 通知 payload.entity_type=volunteer_activity 时活动必须存在
I9 跨租户数据零泄漏
I10 取消报名后名额释放
```

## 6. 执行顺序

### Phase 0（0.5h）

- 备份 DB/uploads；
- 建 UAT 租户与账号（admin/operator/worker/自定义角色）；
- 跑 tsc/build；
- 确认迁移 116 已应用。

### Phase 1（0.5 天）API 全功能

- 活动/报名/取消/签到/签退/核销/积分/黑名单/导出/通知；
- 负向、边界、权限、隔离；
- 并发用例；
- 数据不变量校验。

### Phase 2（0.5 天）PC + 小程序 API

- Playwright 志愿者页全流程；
- 小程序 API 全流程；
- 通知/导出/二维码检查。

### Phase 3（0.5 天）真机

- iPad + HarmonyOS；
- 扫码签到、报名/取消/签到/签退、错误提示、布局；
- 真实微信不涉及（本轮通知仅站内信）。

### Phase 4（0.5h）

- 全量回归；
- 清理校验；
- 报告。
