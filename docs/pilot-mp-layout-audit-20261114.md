# 小程序端布局与交互审计（2026-11-14）

> 方式：直接读当前 `pages/**/*.wxml|wxss|js` 与 `components/tab-shell`，按角色首页、模块入口、按钮层级、触控尺寸、空态/错误态逐页核对。
> 不含业务逻辑正确性（另有专项）；不引用此前测试结论。

## 1. 当前信息架构

```text
居民/未登录   报修(首页) · 记录(我的报修) · 我的(个人中心)
工人          工作台 · 待办 · 我的
调度员        调度台 · 我的
受理台        受理台 · 我的
运营(admin)   总览 · 我的
复核员        复核台 · 我的
```

- 底部导航由 `components/tab-shell` 自绘，按角色 2~3 格，固定底部并适配安全区。
- 工人有独立「待办」；其余角色只有两格（`tab-shell.js:9-15` 注释说明待办页未建）。

## 2. 模块覆盖结论

## 3. P1：影响完成主任务

### P1-1 工作台与「待办」两个 Tab 的任务列表高度重复

- 现象：两个页面都渲染「在办 / 已完成」Tab，同样的任务卡（实体、状态、SLA、时间）；工作台额外有统计、抢单入口和工具九宫格。
- 证据：`pages/worker/workbench/workbench.wxml:46-85`、`pages/worker/todo/todo.wxml:18-59`；两个 Tab 都在 `tab-shell` 工人三格内。
- 影响：工人不知道该看哪一页；两页都要维护加载/刷新/空态；任务一多，用户在两格之间来回切。
- 可选方案：
  - A. **工作台 = 仪表盘**（统计、抢单、工具），任务列表只留在「待办」。改动小、心智最清楚。约 0.5–1 天。
  - B. 工作台只展示「今日/紧急前 3 条」，待办展示全部。保留快捷入口，但两页仍有交集。约 1 天。
  - C. 合并两页，第二格改为「抢单」或「消息」。改动最大，需重排导航。约 1–2 天。

### P1-2 工单详情：主操作被 AI 建议和现场反馈挤到页面中部；材料入口双轨

- 现象：页面顺序是 头卡 → 任务信息 → **现场反馈按钮** → **AI 处置建议** → **状态动作条** → 更换件 → 耗材领用 → 处理记录。主操作（接单/到场/完成）不在首屏，也不固定。
- 证据：`pages/worker/task-detail/task-detail.wxml:32`（现场反馈）、`:34-56`（AI 建议）、`:59-63`（动作条）、`:67`（更换件）、`:70-77`（耗材领用）。
- 影响：工人打开任务后要滑过一条 AI 卡片才能点“接单/完成”；“更换件（记录现场换件）”和“耗材领用（真实扣库存）”两个入口语义接近，容易点错或重复登记。
- 可选方案：
  - A. **底部固定操作条**：主操作常驻，AI 建议/处理记录折叠；材料入口合并为“用料”按状态展示。约 1–2 天。
  - B. 主操作上移到头卡下方，AI 建议默认折叠；材料入口保持两个但加说明。约 0.5–1 天。
  - C. 只合并材料入口，主操作仍随页面滚动。约 0.5 天。

### P1-3 管理端没有跨模块待办，总览 13 项平铺

- 现象：admin/operator/dispatcher/reviewer 只有两格导航；待复核、待审核、待派、预警分散在总览的模块入口里；通知藏在「我的 → 现场工具」。
- 证据：`components/tab-shell/tab-shell.js:41-63`（两格）、`pages/admin/overview/overview.wxml:33-52`（13 项平铺）、`pages/profile/profile.wxml:45-65`（通知入口）。
- 影响：管理员每天要先想“去哪个模块”，无法从首页看到“今天有多少待办”；跨模块异常容易漏。
- 可选方案：
  - A. 增加第三 Tab「待办」，聚合待复核/待审核/待派/预警，带数字角标。约 2–3 天（需新页面）。
  - B. 总览顶部加「待办卡」：计数 + 一键跳到对应模块；Tab 仍两格。约 1 天。
  - C. 只把总览模块入口分组（运营/现场/配置），不加待办。约 0.5 天。

## 4. P2：明显增加操作成本

### P2-1 同一工具出现在两个地方

- 现象：「巡更 / 陪检 / 志愿活动 / 通知」同时出现在工作台九宫格和个人中心「现场工具」。
- 证据：`pages/worker/workbench/workbench.wxml:88-96`、`pages/profile/profile.wxml:45-65`。
- 影响：入口不唯一；两处都要维护；用户不知道哪处是“正式入口”。
- 方案：A. 工作台只留高频（通知/扫资产），现场工具收口到「我的」（推荐，约 0.5 天）；B. 反之，工作台保留全部，个人中心去掉工具区；C. 保留两处但文案区分“快捷/全部”。

### P2-2 “我的”入口重复（最多 4 处）

- 现象：工作台身份卡右上「我的」、调度台/受理台头部「我的」、总览模块列表「个人中心」、底部导航「我的」。
- 证据：`workbench.wxml:19`、`dispatch.wxml:5`、`accept.wxml:8`、`overview.wxml:51`、`tab-shell` profile 格。
- 影响：视觉噪音；同一目的地四个入口，弱化底部导航的“唯一出口”。
- 方案：A. 页面内“我的”全部移除，只留底部导航（推荐，约 0.3 天）；B. 只保留调度/受理台头部（去掉底部导航不现实）；C. 改为“账号”并保留。

### P2-3 关键按钮触控高度与字号偏小

- 现象：
  - 底部导航标签 `20rpx`（≈10px）；
  - 志愿者记录行「签到/签退/审核」`op-mini`：24rpx 字 + 6rpx 上下 padding，≈27px 高；
  - 总览 AI 洞察「处理/忽略」：22rpx 字 + 10rpx padding，≈25px 高；
  - 仓库「入库/出库」：26rpx 字 + 10rpx padding，≈31px 高。
- 证据：`components/tab-shell/tab-shell.wxss:29,52`、`pages/admin/volunteer/volunteer.wxss:47`、`pages/admin/overview/overview.wxss:43`、`pages/admin/warehouse/warehouse.wxss` `.btn-mini`。
- 影响：现场戴手套、强光、走动中点击困难；易误触相邻按钮。
- 方案：A. 统一最小触控高度 88rpx、正文 ≥24rpx（推荐，约 1 天）；B. 只加大“签到/签退/审核/出入库”等高频动作（约 0.5 天）；C. 不改。

### P2-4 巡检执行页：6 个全宽按钮纵向堆叠

- 现象：签到区 2 个按钮、检查项保存、拍照、标记异常、完成巡检依次全宽排列；“完成巡检”在页面最底部。
- 证据：`pages/worker/inspection/inspection.wxml:22-27,40,51,58,63`。
- 影响：正常巡检路径要滑到底才能完成；“标记异常并转工单”与“完成巡检”视觉权重接近，存在误点风险。
- 方案：A. 底部固定主操作“完成巡检”，异常/拍照收进“更多操作”（推荐，约 1 天）；B. 把“完成巡检”上移到检查项之后，异常/拍照放后面（约 0.5 天）；C. 不改。

### P2-5 志愿者管理列表无搜索/状态筛选

- 现象：仅活动列表 + 新建按钮，活动多时只能滑；没有“进行中/已结束”筛选。
- 证据：`pages/admin/volunteer/volunteer.wxml:17-33`。
- 影响：活动一多找不到目标；管理动作（签到/签退/审核）要逐个点开。
- 方案：A. 顶部状态 chips + 关键词搜索（推荐，约 0.5–1 天）；B. 仅状态 chips（约 0.3 天）；C. 不改。

### P2-6 移动端仓库不能设置低库存阈值

- 现象：仓库页有低库存统计与红色标记，但没有设置阈值入口；PC 端才有。
- 证据：`pages/admin/warehouse/warehouse.wxml:18-36`；阈值接口只在 PC `MaterialPage` 接入。
- 影响：仓库管理员在手机上看到低库存却无法定阈值，只能回电脑。
- 方案：A. 库存行增加“设阈值”（推荐，约 0.5 天）；B. 点低库存数字进入批量设置；C. 仅 PC。

### P2-7 通知入口没有未读角标

- 现象：工作台“通知”工具、个人中心“通知”、底部导航都没有未读数；只有进入通知页才看到未读数量。
- 证据：`workbench.wxml:90`、`profile.wxml:60-63`、`tab-shell.wxml` 无 badge 支持。
- 影响：派单/催办提醒到得晚；用户不会主动点开。
- 方案：A. 工具入口/底部导航显示未读角标（推荐，约 0.5–1 天）；B. 只在工作台提示条显示未读；C. 不改。

### P2-8 登录页没有“忘记密码/联系管理员”

- 现象：只有“输入邀请码开通”和折叠的“已有账号登录”；没有密码找回说明。
- 证据：`pages/login/login.wxml:17-53`。
- 影响：历史账号忘记密码时无处可点，只能打电话问。
- 方案：A. 加一行“忘记密码？联系管理员重置”（推荐，0.2 天）；B. 做自助找回（需短信/验证，工作量大）；C. 不改。

### P2-9 空态/错误态不统一

- 现象：有的页面是纯文字“暂无…”，有的是卡片，有的有“重试”，有的只有“加载中…”。
- 证据：`admin/review/review.wxml:25`（纯文字）、`admin/warehouse/warehouse.wxml:28`（empty-mini）、`admin/staff/staff.wxml:58-62`（错误+重试卡片）、`workbench.wxml:51-54`（loading/err/empty 三段）。
- 影响：用户不知道“没数据”还是“加载失败”，也不知道下一步能做什么。
- 方案：A. 统一空态组件（图标+一句说明+主操作），错误态统一“重试”（推荐，约 1 天）；B. 只统一文案与颜色（约 0.5 天）；C. 不改。

## 5. P3：可选的体验优化

- **P3-1 账号权限展示英文 key**：个人中心直接列 `volunteer.manage` 等权限点，对用户无意义。建议隐藏，或改成中文权限名（`profile.wxml:67-73`）。
- **P3-2 版本号散落**：多个页面页脚 `v5.9.26`，占空间且对用户无价值。建议只在“我的”页展示（各页 `.footer`）。
- **P3-3 AI 洞察“忽略”权重过高**：“处理/忽略”等宽并排，“忽略”是抑制建议的动作，建议改为文字按钮或放次级（`overview.wxml:24-27`）。
- **P3-4 我的报修页反馈入口太靠底**：记录多时要滑到底才能反馈，建议移到页头或底部导航附近（`my.wxml:69-76`）。

## 6. 建议实施顺序

### 方向 A：IA 收敛（最影响“知道去哪”）

P1-1 工作台/待办分工 → P2-1 工具入口唯一 → P2-2 “我的”入口唯一。
约 2–3 天，风险低，主要是页面删减与文案。

### 方向 B：现场效率（最影响“干活快不快”）

P1-2 工单详情底部操作条 + 材料入口合并 → P2-4 巡检底部主操作 → P2-3 触控/字号。
约 2–3 天，需要改 WXML/WXSS 与少量交互。

### 方向 C：管理端导航（最影响“会不会漏事”）

P1-3 待办 Tab 或总览待办卡 → P2-7 通知角标 → P2-5 志愿者筛选 → P2-6 仓库阈值。
约 3–4 天，新增页面/接口接入。

### 方向 D：可用性基线

P2-3 触控/字号 + P2-9 空态统一 + P2-8 登录提示 + P3 清理。
约 2 天，跨页修改，视觉收益明显。

### 方向 E：全做

A → B → C → D，约 8–10 天（含真机回归）。
